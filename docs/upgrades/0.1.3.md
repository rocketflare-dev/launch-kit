# Porting note: 0.1.3

## What changed

- `scripts/kit-check.mjs` no longer refuses a provisioned app. Launch's `write_config` step
  commits the real KV ids into an app's `wrangler.toml` and `wrangler.staging.toml`, and the
  checker failed every real id outside `--provisioned` ("must be a <PLACEHOLDER> in the kit"). The
  rule is now:
  - in the kit (no app manifest, or `"app": null`), every id is a `<PLACEHOLDER>`;
  - in an app, an id may be a placeholder (scaffolded, not yet provisioned) or real (provisioned);
  - with `--provisioned` (deploy.yml), no id may be a placeholder.
- The scripts' tests no longer judge the repository they run in. The tests that did ("kit-check
  on this repository", init's run on a copy of the repository) failed in every provisioned app,
  for example in its first deploy Gate. The checker's tests now run on a fixture kit built in a
  temp dir (`scripts/tests/fixtures/kit-fixture.mjs`). The fixture is checked fresh and after a
  provisioning step that does what Launch's `write_config` does. The end-to-end `init` and
  `upgrade` runs and the checks of the kit's own files moved to `scripts/tests/kit-only/`, which
  no app carries.

## What merges by itself

`node scripts/upgrade.mjs --to 0.1.3` merges the checker and the test files, and deletes
`scripts/tests/upgrade.test.mjs`.

## What needs a hand

An app whose Gate already fails (`kit-check on this repository › conforms`, or `fails
--provisioned while the ids are still placeholders`) cannot wait for an upgrade through its own
pipeline. It needs the files replaced by hand from the 0.1.3 tag. In the app's root, run:

```bash
KIT=https://raw.githubusercontent.com/rocketflare-dev/launch-kit/0.1.3
for f in scripts/kit-check.mjs \
         scripts/tests/kit-check.test.mjs \
         scripts/tests/init.test.mjs \
         scripts/tests/manifest.test.mjs \
         scripts/tests/parsers.test.mjs \
         scripts/tests/fixtures/kit-fixture.mjs; do
  mkdir -p "$(dirname "$f")" && curl -fsSL "$KIT/$f" -o "$f"
done
git rm -q scripts/tests/upgrade.test.mjs
```

Do not copy anything under `scripts/tests/kit-only/`: those tests are the kit's own. If your app
changed one of the replaced test files, merge by hand instead. Your tomls stay as they are, real
ids included. Then set `kit.version` in `.launch-app.json` to `0.1.3`.

An app whose display name equals its slug (`wtf` / `wtf`) also failed `init`'s re-rename test.
That test is kit-only now. Running `init` again in such an app still renames the display name
where the slug was meant, so give it a display name that differs from the slug first.

## How to check

`pnpm install && pnpm gate`, then `node scripts/kit-check.mjs --provisioned` once Launch has
provisioned the app.
