# Porting note: 0.1.4

## What changed

- `launch.kit.json` declares where this kit's sign-in returns and where a sign-out lands:
  `launchProvides.oidc.callbackPath: "/auth/callback"` and `signedOutPath: "/"`. Launch registers
  `{environment url}{callbackPath}` as the app's OIDC redirect URI and `{environment url}{signedOutPath}`
  as its post-logout redirect URI. Without the two fields Launch used Rocketflare's paths
  (`/auth/oidc/callback`, `/login?signedOut=1`), and every sign-in to an app made from this kit
  failed with "The address this app asked Launch to return to is not one it registered."
- `signedOutPath` is `/` because the kit does no RP-initiated logout: `POST /auth/logout` ends the
  app's own session, and the UI then goes to `/`. The app never calls the issuer's
  `end_session_endpoint`.
- The two paths live in one place in the code, `apps/web/src/auth/paths.ts`
  (`OIDC_CALLBACK_PATH`, `OIDC_SIGNED_OUT_PATH`). The callback route, the `redirect_uri` the app
  sends and the UI's sign-out all read the constants, and `apps/web/tests/oidc.test.ts` pins them.
- `scripts/lib/kit-manifest.mjs` validates the two optional fields as Launch does. Each must be a
  path on the app's own origin: a single leading `/`, and no scheme, host, whitespace or `#`. When
  a field is absent, the checker applies Rocketflare's default.
- `init` renames an app whose display name equals its slug (`wtf` / `wtf`). Before, renaming such
  an app again replaced the display name first, so `wtf-staging` became `Beta Desk-staging`.
  `scripts/lib/tokens.mjs` now renames in one pass, taking the longest token first at each
  position. When the display name is the slug, each occurrence is renamed as the slug.
- The kit fixture writes Launch's `workers_dev` comment the way `write_config` does (fd7ec72).

## What merges by itself

`node scripts/upgrade.mjs --to 0.1.4 --apply` takes `launch.kit.json` verbatim. It merges
`apps/web/src/app.ts`, `apps/web/src/ui/main.ts`, `apps/web/tests/oidc.test.ts`, the checker and
`scripts/lib/tokens.mjs`, and adds `apps/web/src/auth/paths.ts`. An app that moved its own sign-in
routes resolves those conflicts by hand. Then it makes `paths.ts` and the manifest name the routes
it actually serves.

## What needs a hand

**1. The manifest, if you do not run the upgrade.** Add the two fields to the `launchProvides.oidc`
block of your `launch.kit.json`:

```json
    "oidc": {
      "issuer": "OIDC_ISSUER",
      "clientId": "OIDC_CLIENT_ID",
      "clientSecret": "OIDC_CLIENT_SECRET",
      "only": "AUTH_OIDC_ONLY",
      "callbackPath": "/auth/callback",
      "signedOutPath": "/"
    },
```

Check that `/auth/callback` is the route your app serves (`apps/web/src/app.ts`, or `paths.ts`
after the upgrade). If you changed it, declare your own path instead.

**2. The OIDC client Launch already registered.** Launch registered your app's client before the
manifest said otherwise, with Rocketflare's paths. Fixing the manifest does not rewrite a
registered client, so set its redirect URIs once. Replace `<app>` with the app's slug and
`<domain>` with its domain:

```bash
launch apps sign-in redirect-uris <app> \
  --redirect https://<app>-staging.<domain>/auth/callback \
  --redirect https://<app>.<domain>/auth/callback \
  --logout https://<app>-staging.<domain>/ \
  --logout https://<app>.<domain>/
```

You can do the same in Launch, on the app's Settings page under sign-in. Sign-in works on the next
attempt; no redeploy is needed.

## How to check

`pnpm install && pnpm gate`, then `node scripts/kit-check.mjs`. Sign in on staging: the issuer
returns to `/auth/callback`, and signing out lands on `/`.
